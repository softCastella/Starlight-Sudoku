### Play Console (사용자 입력, 2026-09-11 새벽 기준)

- 앱 생성·패키지 `com.tychespark.starlightsudoku`
- **AAB 등록** (내부 테스트)
- **게시 개요** 진행
- **스토어 설정** 입력
- **이미지/애셋 제출** (아이콘·특집 그래픽·휴대전화 스크린샷 등). 특집 그래픽은 `feature_graphic_v1_1024x500` 손본본 사용
- 스토어 카피: 체험판·Easy 10 명시. 자세한 설명은 콘솔에서 줄바꿈이 안 먹어 **한 줄+·구분**으로 넣음(통과용)
- 타겟 연령: **13~15 / 16~17 / 18+** (5·6~8·9~12 체크 안 함). Designed for Families 아님

### 분석·대시보드 (별도 트랙)

- 대시보드 요구사항은 **11/11 근처까지 한 상태**로 기록(사용자 확인). 작업 브랜치 `codex/starlight-analytics-dashboard`
- collector는 `server/analytics/` (`POST /api/v1/events/batch`). 익명 ID·세션·allowlist 이벤트. 자유 텍스트·IP 없음. `platform` web/android 가능
- WebDemo `collectorUrl`은 기본 **빈 값**(아직 공개 수집 off)
- **지금 Play AAB는 collector를 보내지 않음** → Data safety는 **현재 빌드 기준 「수집 없음」**. Play 앱이 서버로 보내기 시작하는 버전부터 예로 바꾸고 방침 수정

## Data safety 합의 (지금 제출용)

- 질문「필수 사용자 데이터 유형을 수집하거나 공유하나요?」→ **아니요**
- 이유: 이번 내부테스트 AAB에 계정·광고 없음. 진행은 기기만. 우리 서버로 안 보냄
- 구글 로그인·Play→대시보드 전송이 **실제로 들어간 빌드**에서만 Data safety·방침을 갱신

## 후속 작업

### Play 입점 (우선)

1. **내부 테스트 테스터** — 본인 Gmail 추가 → 참여 링크 수락 → Play에서 설치
2. 실기기 확인 — 벌레 없음, Easy 10, 흰 스플래시, 코어 루프
3. 콘솔 남은 항목 — Data safety(**아니요**), 광고=없음, IARC, 앱 액세스(로그인 없음) 등 빨간 항목 클리어
4. 문제 없으면 **프로덕션(또는 다음 트랙) → 심사 제출**
5. (선택) 언어별 스토어 등록정보 en/ja/zh/zh-TW — 기본 ko만 있어도 제출 가능

### 분석·대시보드 (Play와 분리)

1. Vultr/공개 HTTPS에 collector 배포, CORS·보관 정책
2. WebDemo `analytics-config.js`에 `collectorUrl` 넣고 제한 트래픽으로 검증
3. Play APK에 android 전송을 넣을 때만 Data safety·방침 동시 수정
4. `codex/starlight-analytics-server`라는 이름의 로컬/원격 브랜치는 없음. 서버 코드는 `codex/starlight-analytics-dashboard`의 `server/analytics/`
