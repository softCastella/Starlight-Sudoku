# 2026-09-10 후속 작업 (일시정지·다시 풀기 모달)

선행: `Docs/Meeting/2026-09-10_작업.md`. 회귀: `Docs/Harness/검증.md`. APK는 `main`.

다음 UI 조정은 **퍼즐(게임) 화면**이다. 타이틀·설정·크레딧 베이크와 섞지 않는다.

## 1. 일시정지 화면

### 지금

- AppBar 일시정지(`Icons.pause`) → `GameNotifier.togglePause()`만 호출
- 타이머는 멈춤(`isPaused`)
- **일시정지 전용 오버레이·양피지·버튼 행은 없음.** 보드가 그대로 보인다
- 예전에 「일시정지 오버레이」는 미구현으로 적혀 있었다(`2026-09-02` 회의록 등)

### 할 일

1. 일시정지 ON일 때 보드를 가리는 **일시정지 화면**(양피지 또는 전체 오버레이)
2. 문구·버튼은 Play UI 규격(타원 닫기 높이·글자 11, 가운데만 늘림, 모달 패딩 규칙)
3. 재개(계속 풀기)로 일시정지 해제. 나가기면 기존 「퍼즐을 나갈까요?」 흐름과 맞출지 결정
4. 일시정지 중에도 숫자·셀 입력이 먹히면 실패
5. 언어: ko / en / ja / zh / zh_TW

### 확인

- 난이도·스테이지·마을 하늘은 건드리지 않음(스테이지 클리어 비율만)
- 스토어 빌드에 벌레 스킵·UI 슬라이더 노출 없음

## 2. 다시 풀기(다시시작) 누른 뒤 모달

### 지금

- AppBar 새로고침(`Icons.refresh`, tooltip 「다시 풀기」) → **확인 없이** `GameNotifier.giveUp()` 호출
- `giveUp()`은 보드를 퍼즐 초기 상태로 리셋(타이머·실수 등도 같이 초기화되는 쪽)
- 「퍼즐을 나갈까요?」 양피지(`GiveUpPuzzleDialog`)는 **뒤로가기·나갈 때**만 쓴다. 다시 풀기에는 안 붙음

### 할 일

1. 「다시 풀기」를 누르면 **확인 모달**을 먼저 띄운다
2. 확인하면 리셋, 취소하면 그대로
3. 모달은 기존 양피지 계열(`ParchmentModal` + 타원 버튼). 종료·포기와 같은 규격(짧은 창은 글+패딩 높이, 가운데만 늘림)
4. 문구는 「처음부터 다시 풀까요?」류. 이어하기 저장과의 관계를 한 줄로 분명히(리셋이면 현재 판 진행이 어떻게 되는지)
5. Play UI 편집 칩에 넣을지(새 `PlayUiTarget` vs 기존 `giveUp` 재사용) 구현 때 정한다. 언어별 패딩은 필요하면 베이크

### 하지 말 것

- 확인 없이 보드를 리셋하는 지금 동작으로 되돌리기
- 다시 풀기 모달을 Material `AlertDialog`로만 두기(마을 예외 UI와 섞지 않음)
- `sample-v1` 건드림, `pages` 무단 푸시

## 구현 순서 (제안)

1. 다시 풀기 확인 모달(동작이 위험한 쪽을 먼저)
2. 일시정지 오버레이·재개 UI
3. 실기기 APK에서 한·EN 긴 문구·타원 높이 확인
4. 하네스 `Docs/Harness/검증.md`에 퍼즐 일시정지·다시 풀기 항목 추가
